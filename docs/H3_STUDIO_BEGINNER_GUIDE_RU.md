# H3 Studio в ComfyUI — инструкция для начинающих

Это практическое руководство по готовой сборке MiniMax H3 / H3 Studio на твоём ноутбуке
(ASUS ROG Z13, Ryzen AI Max+ 395, 128 GB, ROCm/Vulkan).

Читай сверху вниз. Первый запуск — 10 минут, дальше всё проще.

---

## 0. Что вообще происходит

H3 Studio — это видеомодель MiniMax H3 в интерфейсе ComfyUI. Ты даёшь ей **фотографию**
и **текстовое описание**, она делает **короткое видео**, в котором твой объект оживает:
камера двигается, свет меняется, сцена дорисовывается. Это не «оживление мимики» и не
фоторедактор в классическом смысле — модель перерисовывает сцену, сохраняя объект.

Из этого следуют три вещи, которые надо принять сразу:

1. Результат — **видео**, а не картинка (картинку можно взять как кадр).
2. Модель **не гарантирует побайтовое сходство** лица/объекта. Она сохраняет «суть»:
   одежду, силуэт, общий вид. Чем чище и крупнее объект на фото, тем лучше сходство.
3. Всё считается **локально**, ничего не уходит в интернет.

## 1. Как запустить ComfyUI

ComfyUI живёт в Docker. Один раз на сессию:

```bash
cd ~/workspace/comfyui-strix-halo
docker compose up -d
```

Проверить, что поднялся:

```bash
docker ps | grep comfyui
```

Открыть в браузере:

```
http://127.0.0.1:8188
```

Обрати внимание: порт **8188**, а не 8000.

Остановить, когда закончил (освобождает память):

```bash
cd ~/workspace/comfyui-strix-halo
docker compose stop
```

Посмотреть логи, если что-то не так:

```bash
docker logs --tail 50 comfyui-strix-halo
```

## 2. Как открыть готовый workflow

Workflow лежат в папке:

```
~/workspace/comfyui-strix-halo/workflows/h3-studio/
```

Внутри ComfyUI они уже видны в меню **Workflows** (в левой панели) — папка `h3-studio`.

Файлы:

| Файл | Для чего |
|---|---|
| `H3_STUDIO_1_FAST.json` | быстрые пробы, 4 шага, 768×448 |
| `H3_STUDIO_2_QUALITY.json` | хорошее качество, 8 шагов, 1344×768 |
| `H3_STUDIO_3_2K_FINAL.json` | финал: черновик + latent upscale до 2K |
| `H3_STUDIO_4_UPSCALER.json` | увеличить готовую картинку (без H3) |
| `H3_STUDIO_5_EDITING.json` | редактирование: фон, стиль, окружение |

Как открыть:

1. Меню **Workflows** → `h3-studio` → выбери файл.
2. Или просто перетащи `.json` файл мышкой в окно браузера.

После открытия граф появится на холсте. Он сгруппирован в блоки:

```
[ МОДЕЛИ (не менять без необходимости) ]  [ H3 STUDIO: ФОТО + ПРОМПТ + НАСТРОЙКИ ]
[ ГЕНЕРАЦИЯ → ПРЕВЬЮ → СОХРАНЕНИЕ ]
```

Плюс отдельная жёлтая заметка «Как пользоваться этим workflow» — она всегда справа.

## 3. Как загрузить своё изображение

В графе есть нода с заголовком **«INPUT IMAGE — загрузите сюда своё фото»** (тип `Load Image`).

1. Нажми на неё — откроется окно выбора файла.
2. Выбери фото.
3. Если фото не появилось — нажми `choose file to upload` в той же ноде.

Второй способ (работает и в редактировании): перетащить файл прямо на ноду H3 Studio,
в слот `First frame`.

Требования к фото:

- Формат JPG/PNG, любое разрешение (внутри само приведётся к нужному).
- Лучше **горизонтальное** (16:9), объект целиком, не обрезан по краям.
- Хорошо, если объект крупный и освещён равномерно.
- Не ставь фото с водяными знаками и сильным шумом — модель их «дорисует».

## 4. Где вводить Prompt

Промпт вводится **внутри большой ноды «H3 STUDIO»** (тип `CSGlideCast`), в поле
`prompt`. Это единственное место, где пишется текст.

Правила простого хорошего промпта:

- Пиши по-английски (модель обучена на английском, русский понимает хуже).
- Схема: **что в кадре → что происходит → свет/стиль → камера → звук**.
- 1–2 предложения достаточно. Длинные простыни не помогают.
- Не описывай то, что уже есть на фото (пол, стены, лицо) — описывай **изменение**.

Примеры, которые можно вставить как есть:

```
A cinematic shot of this subject, gentle camera push-in, soft window light, shallow depth of field.
```

```
This person slowly turns their head to the camera and smiles, warm sunset light, film grain, calm ambient sound.
```

```
The subject walks forward through a rainy neon-lit street at night, reflections on wet asphalt, handheld camera, city ambience.
```

```
A product shot: the object rotates slowly on a dark reflective surface, studio lighting, subtle lens flare, no background noise.
```

## 5. Где Negative Prompt

**В этой сборке negative prompt не используется.** Модель дистиллированная (turbo),
она работает без classifier-free guidance, поэтому «негативного» условия в графе нет.
Если очень нужно чего-то избежать — напиши это словами в промпте
(например: `clean background, no text, no watermark`).

---

## 6. Как запустить генерацию

1. Проверь, что фото выбрано и промпт написан.
2. Нажми кнопку **Run** (или `Queue Prompt`) в правом верхнем углу — или `Ctrl+Enter`.
3. Смотри на ноду **превью**: она показывает кадры по мере генерации.
4. По завершении справа в панели появится результат, а файл сохранится в папку `output`.

Первый запуск каждого workflow — долгий: модель (~20 ГБ) и текст-энкодер (~25 ГБ)
загружаются в память. Дальше — быстрее, они остаются в кэше.

Хочешь прервать — кнопка **Cancel** (или `Ctrl+.`).

## 7. FAST MODE — быстрые пробы

Файл: `H3_STUDIO_1_FAST.json`

| Параметр | Значение |
|---|---|
| Разрешение | 768×448 |
| Длина | 121 кадр (≈5 сек) |
| Шаги | 4 |
| Sampler | `er_sde`, scheduler `beta` |
| LoRA | `minimax_h3_fl2v_turbo_4step_v1.0_768p` |

Зачем: проверить идею промпта, понять, куда движется камера, поймать композицию.
Качество ниже, зато быстро. Это твой рабочий режим «пощупать».

Что менять в первую очередь: **промпт** и **seed**.

## 8. QUALITY MODE — хорошее качество

Файл: `H3_STUDIO_2_QUALITY.json`

| Параметр | Значение |
|---|---|
| Разрешение | 1344×768 |
| Длина | 294 кадра (≈12 сек) |
| Шаги | 8 |
| LoRA | `minimax_h3_fl2v_turbo_8step_v1.0` |

Зачем: когда промпт уже нравится — получить нормальную картинку.
Здесь больше деталей, стабильнее текстуры, длиннее сцена.

## 9. Как получить финальный результат 2K

Файл: `H3_STUDIO_3_2K_FINAL.json`

Логика в два прохода:

1. **Черновик** — генерация сцены на 1344×768 (модель `ref2va`).
2. **Latent upscale** — скрытое представление кадра увеличивается 3D-свёрткой.
3. **Дорисовка** — 3 шага `euler` при denoise 0.3 с LoRA `open_h3_regenerate_2k`:
   модель добавляет мелкие детали, а не просто «растягивает» пиксели.

Что делать:

1. Открой `H3_STUDIO_3_2K_FINAL.json`.
2. Фото + промпт как обычно.
3. Запусти. Это самый долгий прогон — наберись терпения.
4. Результат в `output/video/`, файл с префиксом `H3_2K`.

Важно: LoRA `open_h3_regenerate_2k_lora` весит 11.6 ГБ, первый запуск подгружает её
отдельно — тоже долго один раз.

Если 2K не нужен, а качество нужно — используй QUALITY. Разница видна, но не радикальная.

## 11. Параметры простыми словами

| Параметр | Что это | Где в графе |
|---|---|---|
| Prompt | Что ты хочешь получить | поле `prompt` в ноде H3 STUDIO |
| Negative Prompt | Чего не хочешь | **не используется** в этой сборке |
| Seed | Число, задающее «вариант» результата | нода `Random Noise` |
| Steps | Сколько шагов доработки делает модель | `Basic Scheduler` |
| CFG | Строгость следования промпту | **нет** (turbo-модель, CFG=1 внутри) |
| Denoise | Насколько сильно менять исходник | только в 2K-дорисовке (0.3) |
| Resolution | Размер кадра | `width`/`height` в ноде H3 STUDIO |
| Length | Длина сцены в кадрах | `length` в ноде H3 STUDIO |
| Upscale | Увеличение разрешения | нода `Minimax H3 Latent Upscaler 3D` |

### Seed

- Одинаковый seed + одинаковый промпт + одинаковые настройки = **тот же результат**.
- Хочешь новый вариант — поставь `randomize` в ноде `Random Noise` (или нажми
  «control after generate» → randomize).
- Нашёл удачный кадр — **запиши seed**, сможешь воспроизвести и потом менять только промпт.
- Начни с: `fixed`, seed `145215181630199` (стоит по умолчанию).

### Steps

- FAST: 4. QUALITY: 8. 2K-дорисовка: 3.
- Больше шагов → детальнее, но не линейно: 16 шагов при 4-шаговой LoRA дадут грязь.
- Меньше шагов → мягче, «пластилиново», могут появиться артефакты движения.
- **Не меняй steps, не поменяв LoRA.** 4 шага = LoRA 4step, 8 шагов = LoRA 8step.
  Хочешь 20 шагов — убери LoRA (тогда нужен обычный sampler и это будет очень медленно).
- Начни с: как в готовом workflow, не трогай.

### Resolution

- FAST 768×448, QUALITY 1344×768, EDITING 960×544.
- Больше пикселей → детальнее, но память и время растут примерно квадратично.
- Меньше → быстрее, но лицо/мелкий текст «поплывут».
- Держи соотношение сторон примерно 16:9 (или как у исходного фото).
- Начни с: 768×448 для проб, 1344×768 для финала.

### Length (длина)

- 121 кадр ≈ 5 сек, 294 кадра ≈ 12 сек при 24 fps.
- Больше кадров → модель чаще «забывает» объект к концу, растёт память.
- Меньше → стабильнее, но сцена короче.
- Начни с: 121.

### Denoise (только 2K-дорисовка)

- 0.3 — золотая середина: детали добавляются, композиция сохраняется.
- Выше (0.5+) — сильнее перерисовывает, может увести от исходника.
- Ниже (0.15) — почти не меняет, апскейл остаётся «мыльным».
- Начни с: 0.3.

### Upscale

- В 2K-workflow включён всегда (это его смысл).
- Отдельный `H3_STUDIO_4_UPSCALER.json` увеличивает **картинку** в 4 раза
  моделью RealESRGAN x4+, затем приводит к 2048 px.
- Больше итоговый размер → дольше и больше файл, детали не появляются из воздуха.
- Начни с: как есть, 2048 px.

## 12. Режим EDITING — замена фона, стиль, окружение

Файл: `H3_STUDIO_5_EDITING.json`

Здесь модель `ref2va` (reference-to-video): она смотрит на референсы и **сохраняет
персонажа/объект**, меняя окружение.

Как пользоваться:

1. Загрузи фото в `Load Image` (это первый референс).
2. В промпте опиши **что изменить**, а не что сохранить:
   `change the background to a snowy forest at dawn, keep the same person and clothes`.
3. Хочешь несколько референсов — перетащи файлы в слоты `images` внутри ноды H3 STUDIO
   (до 9 картинок).
4. Запусти.

Что работает хорошо: фон, время суток, погода, стиль (film/noir/anime-ish), окружение.
Что работает плохо: точная замена лица на другое конкретное лицо, мелкий текст,
хирургически точные правки «убери этот стакан».

## 13. Если что-то пошло не так

**Долго на первом запуске.** Нормально: 45 ГБ моделей грузятся с диска один раз.
Смотри `docker logs -f comfyui-strix-halo` — там видно, что грузится.

**Ошибка «out of memory».** Закрой браузерные вкладки с другими нейросетями,
проверь, что не запущены другие модели (`docker stats`), и снизь разрешение или `length`.
Если ошибка возникает **сразу при загрузке энкодера** (Qwen3-VL 32B) — используй ноду
`H3 CLIP Loader (GPU)` или готовый файл `H3_STUDIO_1_FAST_GPULoader.json`, см. раздел 15.

**Нода красная / «missing node».** Значит, workflow открыт в другой сборке ComfyUI.
Открой `.json` из папки `workflows/h3-studio` заново — эти файлы проверены под текущую сборку.

**Видео чёрное или пустое.** Обычно не хватило шагов или LoRA не совпала со steps.
Верни steps/LoRA как в готовом workflow.

**Объект «плывёт», лицо меняется.** Уменьши `length` (например 121 вместо 294),
сделай фото крупнее, в промпте подчеркни `keep the same face and clothes`.

**Результат не сохраняется.** Проверь права на `~/workspace/comfyui-strix-halo/output`
и посмотри лог контейнера — там будет путь, куда он пытался писать.

**Совсем непонятно, что происходит.** Открой `H3_STUDIO_1_FAST.json`, ничего не меняй,
нажми Run и посмотри, как выглядит нормальный цикл. Это и есть твоя отправная точка.

## 15. Энкодер в GPU — нода «H3 CLIP Loader (GPU)»

**Зачем она нужна.** Текстовый энкодер Qwen3-VL 32B
(`qwen3vl_32b_minimax_h3_fp8_scaled.safetensors`, 24,7 ГиБ) в штатной ноде `CLIPLoader`
сначала целиком собирается в обычной оперативной памяти. На этой машине оперативки
30 ГиБ, поэтому загрузка обрывалась ошибкой out of memory ещё до начала генерации.
Новая нода читает файл сразу в видеопамять (VRAM), где свободно ~96 ГиБ.

**Как заменить.**

1. Самый простой путь: открой готовую копию `H3_STUDIO_1_FAST_GPULoader.json`
   (оригинал `H3_STUDIO_1_FAST.json` не изменён).
2. Если делаешь вручную: удали ноду `CLIPLoader`, добавь `H3 CLIP Loader (GPU)`
   (двойной клик по пустому месту → в поиске набери `H3 CLIP`), выставь те же два
   значения — файл `qwen3vl_32b_minimax_h3_fp8_scaled.safetensors` и тип `minimax`,
   и соедини её выход `CLIP` туда же, куда был подключён старый `CLIPLoader`.
3. Остальные ноды, промпт, фото и связи не меняются.

Обе ноды дают одинаковый результат: новая просто иначе читает файл.

**Как убедиться, что энкодер реально на GPU.**

- В логе контейнера (`docker logs -f comfyui-strix-halo`) видны строки
  `[H3 CLIP GPU] прочитано ... тензоров | VRAM ...` и `[H3 CLIP GPU] CLIP готов ... VRAM 26.8 ГиБ`.
- На хосте `docker stats --no-stream comfyui-strix-halo` показывает MEM USAGE около
  1–2 ГиБ. Если видишь ~26 ГиБ — энкодер снова грузится в память, значит выбран старый `CLIPLoader`.
- Замеренные цифры: пик оперативной памяти 1,86 ГиБ вместо 24,7 ГиБ, чтение 10,4 с вместо ~62 с.

**Если что-то не работает.**

- «Файл энкодера не найден» — опечатка в имени или файл не скачан:
  `ls ~/workspace/comfyui-strix-halo/models/text_encoders`.
- «CUDA/HIP-устройство недоступно» — контейнер запущен без `/dev/kfd` или `/dev/dri`;
  проверь `docker compose config` в каталоге проекта.
- Ошибка нехватки памяти уже **на GPU** — закрой другие задачи и перезапусти контейнер;
  нода сама повторных попыток не делает.
- Ошибка про numpy/JSON при загрузке — это дефект ноды, а не модели: сообщи её текст,
  файл модели при этом не повреждён.

Нода ничего не пересчитывает и не квантует: 1369 из 1369 тензоров совпали с файлом
(467 квантованных остались в исходном fp8), поэтому качество генерации не меняется.
