### Defects found and fixed during this work
1. **Category facets were a lie** — the library's category list was the validation-error map
   `ERROR_CATEGORIES` with ids (`video`, `enhancement`) that the registry does not use
   (`video-generation`, `image-enhancement`), so 4 workflows were unfilterable and counts summed to
   7 of 11. Fixed with `CATEGORY_ALIASES` + a `WorkflowDef` validator + `iter_categories(present)`.
2. **`/api/models` listed `configs/*.yaml` as models** — 11 SD config files appeared as "installed
   models". Now filtered to real model extensions.
3. **Wan jobs were declared dead while sampling** — the completion budget was 600 s and the timeout
   path said "vanished". Now 1800 s global, per-workflow `timeout_s: 2400` for video, and an honest
   "stopped tracking" message that never interrupts the engine.

### Defects still open (documented, not hidden)
1. `video-t2v-wan22` has never been executed — status stays VALIDATED.
2. The upload endpoint has been probed but never exercised with a real file through the UI.
3. Settings persistence is unit-tested but not browser-tested.
4. One stale job row still reads `failed / "job vanished"` for a run that in fact succeeded
   (the pre-fix watcher). History is not rewritten.
5. No local TTS node exists in ComfyUI 0.15 — only the paid ElevenLabs one. Local speech must be a
   host-side tool (Piper), not a graph.

## 4. Architecture plan — extend, do not rewrite

Kept as is: registry (one JSON per workflow), `Registry` validation/preflight, sqlite job store,
single heavy worker, `ComfyClient`, static frontend, `start.sh`.

New, small additions:
1. **`studio_kind` on `WorkflowDef`** (`image|video|audio|media`) so the UI can group studios without
   a second registry. Category stays for the library filter.
2. **`execution: graph|host`** — host pipelines (ffmpeg: probe/trim/gif/subs/mux/concat) run through
   a `HostToolRunner` with the same job rows, queue and gallery as graph jobs. This is how "Media
   Tools" becomes real without inventing ComfyUI nodes.
3. **Presets + favourites + rerun** — presets are JSON files next to workflows; rerun clones a job's
   params into the run form.
4. **Model manager additions** — integrity (size + optional SHA-256), duplicates by (folder,size,hash),
   compat notes, dependency→workflow back-references (already derivable from the registry).
5. **Diagnostics page** — engine stats, node-diff vs registry requirements, disk/RAM headroom,
   last test run summary.
6. **Readiness gate in the UI** — the run button is disabled with the exact reason
   (`NEEDS_MODELS: wan2.2_vae.safetensors`) instead of failing after submission.

**Why not more:** a second registry, a task queue or a React frontend would be a rewrite. The current
contract (JSON file → validated graph → job → output) already covers 107 entries.

## 5. Resource strategy for 96 GiB unified / 30.5 GiB host RAM

- One heavy job at a time (already enforced: `one_at_a_time: True`).
- Per-workflow `timeout_s` (video 2400 s) — done; timeouts never interrupt the engine.
- Preflight before submit: models present, node classes present, input file exists, alpha requirement,
  disk free ≥ 5 GiB, and a VRAM warning when `min_vram_gb` exceeds free VRAM.
- `[ESTIMATE]` VRAM ceilings to encode in the registry: SDXL ≈ 12 GiB, Qwen-Edit fp8 ≈ 40 GiB,
  Wan 5B ≈ 45 GiB (measured: 76.6 GiB free of 96 while idle), Wan 14B ≈ 70 GiB.
- Reject obviously impossible combinations (two video models at once) with a clear message.

**Stage 3 — no downloads (can start now):**

   `inpaint-animagine`, `img2img-turbo`, `outpaint-animagine`, `tile-upscale-vram`, `img2img-batch`.
4. Presets, favourites, rerun, diagnostics page, gallery filters by kind.
5. Finish the docs set (`README`, architecture, installation, operations, testing, security,
   troubleshooting, performance benchmarks, implementation status).

**Stage 4 — after approval:** install the chosen package, verify sizes/hashes, register models,
implement the unlocked workflows, run one real test per workflow family.

**Stage 5 — media expansion:** audio first (ACE-Step + Piper are the cheapest wins), then Qwen-Edit,
then video (LTX/Wan A14B), then ControlNet/depth.

**Stage 6 — release validation:** full pytest, browser pass over every route, restart-survival test
(kill uvicorn mid-queue, verify jobs reconcile), gallery kind matrix, security check (binding, path
allow-list, no cloud calls).

## 7. Acceptance criteria

- 100+ registry entries, statuses honest, no duplicates; `READY` only with an inspected output.
- Every `NEEDS_*` entry names the exact missing file or node class in the UI.
- Gallery renders image, video and audio (player per kind), counts types separately.
- Upload → run → output → gallery → rerun works in the browser for one image and one video.
- Settings survive a restart (browser-verified).
- Restart during a running job reconciles to a truthful state (no "vanished" lies).
- `pytest tests` green; integration tests run against the live engine, not mocks.
- Docs match the code; measured numbers only, `[ESTIMATE]` where measured is unavailable.
- Nothing downloaded without approval; nothing deleted; app still bound to 127.0.0.1.

## 8. Test strategy

- **Unit** — registry validation, category canonicalisation, model listing filters, param binding,
  host-tool argv construction, gallery kind mapping.
- **Integration** — live ComfyUI: node presence per workflow, submit + completion, output kind.
- **Browser** — Playwright/CDP: every route, one real generation, video playback, settings round-trip.
- **Restart** — kill the server with a job queued; verify reconcile output.
- **Never** mark READY from JSON parse alone. Expensive runs: one per workflow *family*, not per entry.
