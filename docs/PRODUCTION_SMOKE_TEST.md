## 6. Оговорка: кэш браузера после смены аккаунта

Одно наблюдение требует явной фиксации, потому что внешне выглядит как утечка, но ею не является.

Ход проверки: под `polina` её картинка была загружена в браузер (`/api/outputs/…/turbo_00001_.png`,
ответ 200 с `Cache-Control: private, max-age=3600`). После входа под `sveta` тот же URL вернул 200
с байтами — но запрос с `cache: 'no-store'` на тот же URL дал 404, а файл, который этот браузер
не запрашивал (`tts_ru_RU_00001_.wav` от `polina`), дал 404 и без обхода кэша.

Вывод: **серверная изоляция держится**; 200 пришёл из локального кэша браузера, оставшегося от
предыдущей сессии в том же профиле. Практическое следствие для семьи: если все пользуются одним
профилем браузера, ранее просмотренный чужой файл может открыться из кэша ещё до часа. Это
свойство HTTP-кэша, а не прав; для полного разделения нужны отдельные профили браузера или
инкогнито-окна на каждого. Функциональность в рамках этого теста не менялась и не расширялась.

## 9. Наблюдения, не связанные с этим тестом

Фиксирую, чтобы они не выглядели найденными сейчас:

1. **preflight сообщает 1 error на задачу и всё равно ставит её в очередь** (`jobs.py:501–537`,
   warn-first, `graph_strict` выключен). Так было и до теста: те же предупреждения есть у задач
   владельца в 07:54–16:17 UTC (`vlm-caption`, `asr-large`, `img-thumb-320`). Задачи проходят,
   но причина «одной ошибки» не разобрана.
2. **Админский список задач не показывает владельца.** В JSON задачи нет поля владельца
   (`user_id`/`owner`), поэтому `/api/jobs` под `admin` отдаёт 150 задач без атрибуции. Данные
   не утекают, но разбирать «кто что запускал» через этот экран нельзя — есть `/api/users/usage`.
3. **`/api/me/usage` под `admin` считает только собственные выходы:** 16 задач и 21 выход, тогда
   как Gallery отдаёт 169. Это неверная формулировка экрана, а не прав.
4. **PNG в папке владельца принадлежит `root:root`** (пишет контейнер ComfyUI), WAV — `dmitry`.
   Чтение работает, но владелец файла не совпадает с владельцем каталога.
5. Открытые вопросы code review по `jobs.py` (идемпотентность `_scope_output`, пустые каталоги
   отменённых задач) этим тестом не затрагивались и не исправлялись.
