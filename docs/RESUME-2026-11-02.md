Scratch-инстанс для браузерных сценариев (**сейчас остановлен, порт 8127 закрыт**):

```bash
cd studio && ./.venv/bin/python -u cache/scratch_server.py > /tmp/wfstudio.log 2>&1 &
./.venv/bin/python cache/scratch_login.py admin      # cookie-jar → /tmp/wfs_session.json (0600)
./.venv/bin/python cache/scratch_login.py user       # то же для wfuser
```

**Важно про scratch:** `prepare()` делает `shutil.rmtree(ROOT)` на каждом старте. После рестарта
все тестовые workflow, пользователи и id пропадают (id пользователей тоже новые). Поэтому
браузерные сценарии всегда идут цепочкой: сначала B (импорт+save), потом C (правка+возврат) —
на одном и том же запуске инстанса.

Как зайти браузером: `browser_exec` → `Network.setCookie` для `studio_session` и `studio_csrf`
из `/tmp/wfs_session.json` (url-скоуп `http://127.0.0.1:8127/`), затем `Page.reload`.
Без перезагрузки после установки cookie SPA остаётся на экране логина.
